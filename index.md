# Data Description
## Introduction
My field is in civil and construction engineering, and I will be conducting an informative research study on Navisworks 4D and clash detection software. This software is widely used in construction to integrate multiple 3D models from different engineering/construction disciplines and identify conflicts (or clashes) between them. Examples of these clashes would be utility overlaps, and constructability issues. In addition to clash detection, Navisworks enables 4D modeling by linking the 3D model with the project schedule. This allows users to visualize construction sequencing over time. Navisworks also has the capability to improve planning, coordination, and communication among project stakeholders. The primary objective of my research is to evaluate the effectiveness and practicality of Navisworks in building construction projects. Some key questions I want to answer are: Does Navisworks save time and money in the long run? How reliable is Navisworks? How long does it typically take to train an employee to become proficient in the software? What are the associated costs for companies using Navisworks, including licensing, training, and changing the existing workflows?

## Dataset
My research will rely heavily on: 
- Scholarly articles
- Industry reports
- Case studies

These will help build an understanding of Navisworks and its applications. However, to help strengthen my analysis, I plan on generating a dataset which will allow for quantitative comparisons between projects using Navisworks and projects that did not. Once the data is collected, it will be organized into a spreadsheet with a target of roughly 200 entries.

The dataset will include key features:
- Project type (e.g., commercial, residential, infrastructure)
- Project context (hospital, school, roadway, etc.)
- Total project duration
- Project size
- Total cost
- Average manpower
- Project efficiency

# Data Sharing and Preservation
Since my research dataset will be constructed primarily from scholarly articles, reports, and case studies, there are minimal ethical or legal concerns related to this project (even concerning human subjects). The dataset will not contain personal information, just project details. However, some protection may be necessary regarding intellectual property and proper citation of materials. Since portions of the dataset will be derived from published literature, I'll ensure all metadata is documented and credited in the metadata section. These protections won't limit my ability to share the dataset. I'm not distributing the copyrighted source documents directly. I will provide citations and links to the original publications. Technical limitations on sharing should be minimal because the sum of project files is estimated to remain under 100 MB. 

All project files will be made publicly available after the completion of research project using the generalist repository, Zenodo. This is because there aren't many repositories that are tailored for my specific field. Data will also be shared through Box storage. The primary file formats used for sharing will include .csv files for the dataset, .txt or .md files for metadata, and .r, and .py files for source code created in R, and Python. I will apply a Creative Commons Attribution (CC BY) license to the dataset and other documentation so researchers can reuse, redistribute, and build on my work, just as long as proper credit is given.

Primary access to the data will be maintained through the Zenodo repository. A couple reasons for using Zenodo is because its classified as a GREI (Generalist Repository Ecosystem Initiative) repository and they have a very appealing preservation policy. They project that data will be maintained at least 20 years, and allow CC BY-assigned datasets. 

Data will also be preserved in Box and local backups stored in the project folders. I will follow the 3-2-1 backup rule to ensure preservation through multiple copies and offsite storage. To execute the 3-2-1 rule, my primary copy will be in my local project folder, my backup copy in an external USB drive, and an offset copy in Box storage. Since I'm using Box, project files are automatically synced to protect against forgetfulness to update, and low maintenance. With a USB drive as a backup, manually updating is required to maintain preservation. Preserved files consist of the .csv dataset, metadata, and code files in R, Python, and MATLAB formats. Local copies of all project files will be maintained while also maintaining the archived cloud copies to reduce the risk of losing the data.
